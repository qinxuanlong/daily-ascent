## 一、 核心原则与设计哲学

### 1.1 先把“打卡”重新定义
在传统打卡软件中，“打卡”往往被异化为一个简单的勾选按钮，用户没有任何认知投入，只留下虚假的安慰剂效应。

在 **Daily Ascent (每日攀升)** 中，打卡被重新定义：
> **打卡 = 一次真实专注结束 + 写下成果产出 + 生成一条专注日志 (`CheckInLog`, `source = 'focus'`)**

- **`TodoItem.completed` 只是展示状态，不是打卡本身**。
- **真正算数的是 `CheckInLog`**：并且必须是未被删除、`source = 'focus'`、有效时长 $\ge 5$ 分钟的专注日志。
- **一句话铁律**：**没有专注日志，就没有经验值、没有连击天数、没有今日专注时长。**

### 1.2 高意义感闭环模型
```
[1. 极速启动]               [2. 过程专注]             [3. 成果沉淀 / 打卡]
点开即开始 (一键进入)   -->   番茄倒计时/正向计时   -->   倒计时结束弹出聚焦小卡片：
无需复杂的先期设置           沉浸进入单线程状态         “本次完成了什么？”(必须写下核心产出)
                                                    盖章入库生成一条黄金成果资产卡片
```

- **零阻力启动**：打开页面即为专注发射台，当前待办自动前置，空格键一键开启。
- **真实时间投入**：支持 25m 番茄、45m 深度工作、自由心流正向计时。
- **有形资产转化**：必须写下产出方可盖印，赋予 `+50 EXP`。
- **补记通道隔离**：提供快捷“补记备忘”通道（标记为 `manual`），仅作备忘录入，**不给经验、不计连击、不计专注时长**。

## 二、 核心功能全景解析

### 2.1 今日打卡与专注发射台 (Focus Launcher & Timer)
首页核心区域即为单线程专注发射台，提供三大状态自适应流转：

#### (1) 发射台就绪态 (Launcher State)
- **智能置顶待办**：自动抓取当天按排序权重最近未完成的任务作为当前焦点。
- **支持外部联动聚焦**：在待办清单中点击任意未完成任务圆环，自动跳转至发射台并预选该任务。
- **任务目标快速细化**：提供输入框，可直接补充具体专注子目标（如“攻克动态规划空间优化”）。
- **三档专注模式**：
  - `25m 番茄`：经典 25 分钟番茄倒计时。
  - `45m 深度`：45 分钟深度专注。
  - `自由心流`：正向心流秒表（Stopwatch）。
- **音频唤醒与启动**：用户点击发光主按钮或按 `Space` 启动时，主动触发 `resumeAudioContext()` 唤醒浏览器音频上下文，杜绝计时结束因浏览器安全策略出现静音阻断。
- **补记成果入口**：底部提供“📝 补记一条成果备忘”入口，明确标明不计连击与时长。

#### (2) 沉浸专注中状态 (In-Focus State)
- **呼吸光晕脉动圆环 (Breath Halo Ring)**：配合黑曜石深色背景温和脉动。
- **自由心流超时保护**：若处于自由心流正向计时且单次时长 $\ge 2$ 小时（120分钟），顶部高亮闪烁提醒：“心流已超 2 小时，建议及时收工复盘”。
- **弹性操作坞**：
  - **暂停 / 继续**：中途遇临时打扰一键暂停。
  - **收工并沉淀成果 (Finish Early)**：提前完成任务随时结算，绝不浪费时间或强行判定失败。
  - **放弃**：若被不可抗力打断，取消本次计时。

#### (3) 成果沉淀与盖章归档弹窗 (Outcome Capture Dialog)
- **听觉反馈**：倒计时自然到点或点击收工，播放原生合成清脆空灵磬铃音（528Hz 和平音 + 880Hz 泛音）。
- **成果必须填写校验**：“本次完成了什么？”为**必填项**；内容为空或仅包含空格时，**禁用盖章按钮**，无法蒙混过关。
- **时长校对与防误操作保护**：
  - 成果弹窗内支持人工校对本次专注时长（分钟）；
  - 若专注记录时长超过 4 小时（240分钟），点击保存时弹出二次确认，防止用户忘记停止计时导致数据失真。
- **盖章通关动效**：点击“盖章归档 (+50 EXP)”后，金印压下、粒子迸发，生成成果流水，标记待办完成。

#### (4) 全通关庆祝态 (All-Clear Celebration)
- 当日全部待办任务均打卡完成后，发射台无缝切换为全通关卡片。
- 展示金色星芒奖章徽标、当日总专注时长、真实成果条数、连续天数。

### 2.2 待办列表管理与打卡规则 (Task Manager)

#### (1) 待办打卡圆环铁律
- **未完成待办，点击圆环**：**严禁一键打卡！** 点击直接跳转至首页今日打卡发射台，并预选当前任务，引导用户开启专注。
- **已完成待办，点击圆环**：仅取消待办完成标记（`completed = false`），**绝不删除已生成的成果日志，绝不回退经验**。
- **删除成果**：若确实需要删除错误成果，必须前往“成果时光轴”执行删除，触发软删除并严格重算经验。

#### (2) 任务属性双轨制
- **每日习惯 (`habit`)**：
  - 适合每日必须推进的功课。
  - 每日 05:00 睡切日自动重置为未完成态，持续累加连击天数。
  - 连击天数由该任务关联的有效专注日志（$\ge 5$m）严格重算。
- **临时待办 (`once`)**：
  - 适合当天随时添加的单次任务。
  - 当天完成打卡后，在次日 05:00 睡切日自动清理归档。

#### (3) 软删除与管理
- 待办支持添加、行内编辑标题与计划时间、分类筛选胶囊。
- 点击删除执行软删除（标记 `deleted = true` 与时间戳），保障多端同步时不被复活。

### 2.3 顶部综合进度与量化仪表盘
- **今日专注 N 分钟**：严格聚合当天归属日内 `!deleted && source === 'focus'` 的专注时长总和。
- **沉淀 M 条成果**：统计今日真实专注成果数；若有补记，额外注明 `(+K 补记)`。
- **任务完成比率**：`已完成 / 总待办 (百分比)`。
- **金色星轨流光进度条**：原神暗金渐变进度条，随打卡动态推进。
- **等级与经验值**：`Lv. = Math.floor(exp / 100) + 1`，经验值完全由真实有效日志重算驱动。

### 2.5 坚果云 WebDAV 跨端同步与软删除合并引擎

#### (1) 增量与软删除防复活合并算法
解决传统“并集去重”导致已删除数据在多端同步时被复活的顽疾：
1. **以唯一 `id` 寻址**：遍历本地与云端两份数据。
2. **时间戳比对 (`updatedAt`)**：若两端均存在同一条记录，以 `updatedAt` 较新的一方为准。
3. **软删除剔除防复活**：如果最新的记录标记为 `deleted = true`，**直接在合并产物中剔除**，不再保留，绝不复活！
4. **经验值强制重算**：合并后的数据直接调用 `recalcExp(mergedLogs)` 严格重算，**杜绝使用 `Math.max` 虚假保底**，确保误操作或脏数据可以被正常回退。

#### (2) 自动化静默同步
- 设置中开启“打卡后自动同步”后，每次专注完成或添加待办，后台静默自动合并并上传云端。
- 顶部导航栏常驻旋转云同步按钮，支持手动一键同步与连接探测。

### 2.6 生产环境 WebDAV 代理架构方案 (解决 CORS)

#### 背景说明
Vite 内置的 `/api/dav/` 代理仅在本地开发环境 (`npm run dev`) 下生效。当静态部署至 GitHub Pages 或其他静态托管平台时，由于浏览器同源策略（CORS），前端直接请求 `https://dav.jianguoyun.com/dav/` 会被浏览器拦截。

系统已在设置中提供「服务地址配置」项，提供两种最佳实践方案：

#### 方案 A：使用免费 Cloudflare Worker 搭建轻量反向代理 (推荐)
只需 5 分钟在 Cloudflare 创建一个免费 Worker，将前端 WebDAV 请求透明转发并加上 CORS 允许头：

```javascript
// Cloudflare Worker 反向代理脚本 (proxy-worker.js)
export default {
  async fetch(request, env) {
    const originUrl = new URL(request.url);
    const targetBase = "https://dav.jianguoyun.com/dav";
    
    // 构造转发目标 URL
    const targetUrl = targetBase + originUrl.pathname.replace(/^\/api\/dav/, "") + originUrl.search;

    // 处理浏览器预检 OPTIONS 请求
    if (request.method === "OPTIONS") {
      return new Response(null, {
        headers: {
          "Access-Control-Allow-Origin": "*",
          "Access-Control-Allow-Methods": "GET, HEAD, POST, PUT, DELETE, OPTIONS, PROPFIND, PROPPATCH, MKCOL, COPY, MOVE, LOCK, UNLOCK",
          "Access-Control-Allow-Headers": "Authorization, Content-Type, Depth, Destination, If-None-Match, Overwrite",
          "Access-Control-Max-Age": "86400",
        },
      });
    }

    // 复制请求头并重写 Host
    const headers = new Headers(request.headers);
    headers.set("Host", "dav.jianguoyun.com");

    const newRequest = new Request(targetUrl, {
      method: request.method,
      headers: headers,
      body: request.body,
      redirect: "follow",
    });

    try {
      const response = await fetch(newRequest);
      const newResponseHeaders = new Headers(response.headers);
      newResponseHeaders.set("Access-Control-Allow-Origin", "*");
      newResponseHeaders.set("Access-Control-Allow-Headers", "*");

      return new Response(response.body, {
        status: response.status,
        statusText: response.statusText,
        headers: newResponseHeaders,
      });
    } catch (err) {
      return new Response("Proxy Error: " + err.message, { status: 502 });
    }
  },
};
```
**配置方式**：部署 Worker 后，在 Daily Ascent 设置弹窗中的「服务」输入框中填入 Worker 地址（如 `https://dav-proxy.yourname.workers.dev/`），即可在 GitHub Pages 上完美实现多端跨域自动同步！

#### 方案 B：纯静态离线环境使用 JSON 导出/导入
若不想配置服务端代理，系统内置完整的离线优先机制：
- 数据 100% 存储于本地 localStorage；
- 点击右上角设置 $\rightarrow$ 「导出备份 (JSON)」与「导入备份 (JSON)」进行多设备冷迁移。

## 三、 核心业务机制与算法逻辑

### 3.1 打卡的核心定义与经验值重算机制
```typescript
/**
 * 经验值重算函数 (recalcExp)
 * 铁律：仅统计未软删除 (!deleted) 且真实心流 (source === 'focus') 的日志
 * 补记日志 (manual) 赋予 0 经验，不参与累加
 */
export function recalcExp(logs: CheckInLog[]): number {
  return (logs || [])
    .filter((l) => !l.deleted && l.source === 'focus')
    .reduce((sum, l) => sum + (l.exp || 0), 0)
}
```

### 3.2 05:00 睡到睡切日跨日与开始时间归属机制
针对夜猫子与深夜学习场景，采用 05:00 睡切日判定，且**严格依据专注的“开始时间”进行归属划分**：

```typescript
/** 获取业务游戏日 (05:00 切日) */
export function getGameDate(now: Date = new Date()): string {
  const d = new Date(now)
  if (d.getHours() < 5) {
    d.setDate(d.getDate() - 1)
  }
  return formatDate(d)
}

/** 跨 05:00 切日按专注“开始时间”进行业务日归属 */
export function getGameDateByStart(startedAt: Date | string): string {
  const d = typeof startedAt === 'string' ? new Date(startedAt) : new Date(startedAt)
  return getGameDate(isNaN(d.getTime()) ? new Date() : d)
}
```
**场景举例**：用户于凌晨 04:50 开启 45 分钟专注，05:35 结束并盖章，该记录的业务归属日期严格认定为**前一天**，连击与当日统计平滑承接。

### 3.3 连续打卡天数 (Streak) 严格算法
```typescript
export function calculateStreak(logs: CheckInLog[] = [], todayStr: string = getGameDate()): number {
  if (!logs || logs.length === 0) return 0

  // 1. 严格过滤：必须是未删除、真实心流、且单次专注时长 >= 5 分钟
  const validFocusLogs = logs.filter(
    (log) => !log.deleted && log.source === 'focus' && (log.durationMinutes || 0) >= 5
  )

  // 2. 提取去重的所有有效打卡业务日
  const uniqueDates = Array.from(new Set(validFocusLogs.map((log) => log.date))).sort().reverse()
  if (uniqueDates.length === 0) return 0

  let streak = 0
  let checkDate = new Date(todayStr)

  // 今天若未打卡，检查昨天是否打卡；若昨天也未打卡，则连击归零
  if (!uniqueDates.includes(todayStr)) {
    const yesterday = new Date(checkDate)
    yesterday.setDate(yesterday.getDate() - 1)
    const yesterdayStr = formatDate(yesterday)
    if (!uniqueDates.includes(yesterdayStr)) {
      return 0
    }
    checkDate = yesterday
  }

  // 逐日向前倒推连击天数
  while (true) {
    const currStr = formatDate(checkDate)
    if (uniqueDates.includes(currStr)) {
      streak++
      checkDate.setDate(checkDate.getDate() - 1)
    } else {
      break
    }
  }

  return streak
}
```

### 3.4 WebDAV 软删除与防复活合并算法
```typescript
// 1. 合并历史流水 logs：按 id 去重，以 updatedAt 较新者覆盖
const logMap = new Map<string, CheckInLog>()
allLogs.forEach((item) => {
  if (!item || !item.id) return
  const idKey = String(item.id)
  const existing = logMap.get(idKey)
  if (!existing || (item.updatedAt || 0) >= (existing.updatedAt || 0)) {
    logMap.set(idKey, item)
  }
})

// 2. 最新版本为 deleted = true 的直接过滤剔除，防止复活
const mergedLogs = Array.from(logMap.values())
  .filter((l) => !l.deleted)
  .sort((a, b) => `${b.date} ${b.time}`.localeCompare(`${a.date} ${a.time}`))

// 3. 经验值严谨重算
const finalExp = recalcExp(mergedLogs)
```
